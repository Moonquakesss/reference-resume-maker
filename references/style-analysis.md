# 参考样式分析

仅在用户提供参考 PDF、图片或现有简历时读取本文件。目标是提取视觉规则，而不是复制参考文档的文字。

## 分析顺序

先确认页数、页面尺寸和方向，再将参考 PDF 转为 220–300 DPI 图片。整页只用于判断总体结构；当文字密集或预览缩小时，按阅读顺序分块审阅。检查顶部留白、姓名位置、联系信息结构、正文边界、栏目顺序、页底留白和是否存在多栏。

随后识别字体体系。使用 `pdffonts` 查看嵌入字体；不要只根据 CSS 字体名称判断最终效果。除非用户明确指定其他字体，默认使用技能自带字体：中文、标题、联系信息和中文强调文字使用 `Noto Sans CJK SC` Regular/Bold；正文中的英文与数字使用 `Noto Serif` Regular/Bold，并以 `Noto Sans CJK SC` 补齐中文字符。生成脚本应通过 `@font-face` 引用 `assets/fonts/` 中的字体，禁止静默回退到 PingFang、STSongti、Times New Roman 等系统字体。导出后再次运行 `pdffonts`，确认四种 Noto 字体均已嵌入。用户明确指定其他字体时，以用户要求为准，并同样验证实际嵌入结果。

最后记录颜色和层级。用户指定主题色时以该值为唯一强调色；默认仅用于模块标题、主分隔线，以及工作经历和项目经历的同级小标题。正文使用深灰，正文段落、项目描述和列表中的加粗统一使用 `#202020` 黑色与字重 `700`，不要再用主题蓝突出正文关键词。这样让蓝色稳定表达层级、黑色稳定表达局部强调。避免渐变、阴影、卡片和大面积色块，除非参考文档明确采用这些元素。

## 工作方向样式

当工作经历中的段落以 `**方向**：` 开头时，仅把冒号后的原文包装为 `.direction-tag`。默认使用 `11.5px`、`#6B7280`、字重 `500`，保持行内展示，不使用淡灰底、圆角、描边、内边距或阴影。冒号与后续文字之间不添加空格、外边距或额外字距；如果 Markdown 原文已有空格，则按内容保真规则保留。`方向：` 本身继续沿用工作经历正文尺寸，其中“方向”按正文加粗规则使用黑色。

## 布局复刻边界

参考文档只决定字体、字号、行高、缩进、标题线、留白和颜色等视觉属性。原始 Markdown 必须是唯一文字来源。不要从参考 PDF 抄入姓名、项目、日期、图标文本或其他内容；不要为了适配版面重写经历。

若参考文档是多页而用户要求单页，优先保持用户的页数约束。先调节正文行高、段落间距、列表缩进和模块间距，再小幅调整字号；不得通过删除或改写文字实现单页。
